# 🕯️ ofrenda

### A ghost story where the ghost is someone you love.

**Answer seven questions about a person you miss. A language model running on your own laptop writes their remembrance. You get a candlelit altar page you can keep forever.**

No cloud. No account. No API key. No upload. Nothing leaves your machine.

## The idea

On Día de los Muertos, families build an **ofrenda**: an altar with the food, the song, the flowers, and the stories of people who have died. The ritual says someone stays present as long as someone tells their story.

The stories are the fragile part. They live in a few heads and a few chat threads. If you hand them to a cloud AI to help you write them down, you upload your grandmother's last recipe to a company's server.

`ofrenda` keeps the ritual and removes the server.

## How it works

```
  7 questions          local open-weight model          one HTML file
 ┌───────────┐        ┌────────────────────────┐       ┌──────────────┐
 │ who       │        │ Ollama on localhost    │       │ candle flames│
 │ food      │  ───►  │ gemma3 / llama3.2 / …  │  ───► │ marigold glow│
 │ song      │        │ "use ONLY facts given" │       │ the story    │
 │ story …   │        └────────────────────────┘       └──────────────┘
 └───────────┘          no network after model pull      works offline
```

1. A terminal interview asks for a name, a relationship, a food, a song, a scent, a phrase they always said, and one story you never want to lose.
2. Your answers go to a model served by [Ollama](https://ollama.com) on `localhost`.
3. The model writes a short remembrance, bound by a strict system prompt to use only what you told it.
4. `ofrenda` renders a self-contained HTML altar: swaying papel picado banner, flickering candles, drifting marigold petals, the remembrance typed out line by line, and an offerings tier for the food, song, flower, and phrase. Open it in any browser, print it, send it to family. Motion turns off for visitors who prefer reduced motion.
5. Optional `--chat`: talk to an **echo**. It answers only from the memories you gave, says "That is not in the memories you shared." when asked about anything else, and tells you plainly it is an echo, not them.

## Quickstart

```bash
# 1. get a model (one time, needs internet)
ollama pull gemma3:4b

# 2. run it (no internet needed from here on)
node ofrenda.mjs
```

Your altar lands in `ofrendas/<name>.html`, with the raw answers in `ofrendas/<name>.json`.

| Want to... | Do this |
| --- | --- |
| Use a different model | `OFRENDA_MODEL=llama3.2 node ofrenda.mjs` |
| Talk to an echo of them after the altar | `node ofrenda.mjs --chat` |
| Run with no model at all | `node ofrenda.mjs --no-ai` |
| Point at another Ollama box | `OLLAMA_HOST=http://192.168.1.20:11434 node ofrenda.mjs` |
| Change output folder | `OFRENDA_OUT=altars node ofrenda.mjs` |

Zero dependencies. One file of logic. Node 18 or newer.

## Why open-weight models are the point, not a detail

This project does not work the same way with a closed API.

| | Open-weight, local (this project) | Closed cloud API |
| --- | --- | --- |
| **Privacy** | Stories about the dead stay on your disk | Uploaded to a third-party server |
| **Offline** | Works with the wifi off | Needs a connection |
| **Longevity** | A model file on your disk cannot be deprecated | Endpoint, pricing, or terms can change under you |
| **Control** | Swap models with one env var, edit the system prompt | Locked to the provider's model and policy |
| **Cost** | Free per run | Metered |
| **Archival** | Output is plain HTML you own | Output lives wherever the service puts it |

A memorial that might vanish when a company changes its API is not much of a memorial.

## Design decisions

**The model is not trusted with facts.** The system prompt tells it to use only details you provided and to leave gaps empty rather than fill them. A remembrance with an invented detail is worse than none.

**The human stays in charge.** Small models can still drift. The output is a draft: `ofrenda` tells you to read it and edit it, and the raw answers are saved beside it so nothing you said is lost.

**The echo is honest about what it is.** Talking to a simulated dead person can go wrong. The echo prints a notice before it starts, never claims to be the person, never invents advice or messages from beyond, and points you to someone you trust if you seem in real distress.

**There is a no-AI mode.** `--no-ai` builds the same page from a plain template. The altar should not depend on a model being installed.

**Private by default.** `ofrendas/` is gitignored so a stray `git add .` does not publish someone's family stories.

**HTML is the archive format.** No framework, no build step, no hosted viewer. A file you can open in thirty years.

## Honest limits

- Small local models write plainer prose than frontier cloud models. That is the trade for privacy and ownership.
- Models can hallucinate even with a strict prompt. Read the result before you share it.
- Interview is English-only for now.

## Roadmap

- Photo slot on the altar, read from a local file path
- Voice input with a local speech model, so elders can tell stories aloud
- Multiple people on one shared altar
- Spanish and other-language prompts
